# AI 取证与回答优化（2026-09-05）

## 本轮改动

- 修复检索仅因“按钮/插件”泛词就命中无关节点的问题；字段中文显示名匹配后，用元数据中的逻辑名扩展检索。
- 最终回答优先包含与问题匹配的证据，再按工具类型和新旧程度排序；相关字段代码不再一律排在无关插件材料之后。
- 相同 JSON 参数不受属性顺序影响，重复只读工具调用返回复用提示，完整结果继续保留在之前消息中。实时数据、诊断状态和有状态的 API 解析不采用该缓存；失败和等待数据的结果不缓存，图节点/关系变化后重新检索。
- 达到证据/上下文预算后转入独立最终回答，而不是重复报错直到超时；仍不限制固定工具调用次数。
- 15 分钟总配置默认预留最后 90 秒用于最终回答与格式修复；正常提前完成时立即生成回答。最终回答阶段的重试共用预留时间。
- 日志记录模型请求耗时、输入字符数、供应商返回的 token 使用量、缓存命中量和结束原因，不记录原始模型输出和业务数据。已有工具 trace 记录各检查耗时。
- AI 失败时显示真实的未完成状态和失败类别，不再用不相关的静态证据列表冒充业务答案。
- 支持当前窗体引用的托管业务脚本/HTML、自定义 API 和实体相关托管插件。仍按当前实体过滤步骤、按实际 API 名或 ID 解析依赖，不扫描组织全量插件。
- 新增 field-value-rules，深化字段可见性、公共 API 分发、空列表筛选诊断。Skill 不规定前端答案的固定栏目。

## 配置

在分析服务器 AI 配置节可设置 `FinalAnswerReserveSeconds`（默认 90，允许 5–180）。实际预留不超过 `MaxInvestigationSeconds` 的一半。`MaxInvestigationSeconds=900` 时，新的调查工具在约 810 秒后停止，最终回答阶段最多使用预留的 90 秒。外部网络调度和取消传递可能产生小量额外耗时。

`MaxContextTokens` 仍为 262144 的容量上限，不要求每轮填满。`MaxEvidenceCharacters` 和 `MaxToolResultCharacters` 仍独立限制证据量。

## 验证与使用

运行 `dotnet test tests/CrmLogicLens.Core.Tests/CrmLogicLens.Core.Tests.csproj`、`node tests/extension-filter-smoke.js` 和 `node --test tests/extension/*.test.cjs`。

重新启动分析服务，Edge 扩展管理页重新加载插件，重新采集当前窗体；已有快照无法自动补回此前被错误排除的组件。

用身份证号填写逻辑、服务类型条件隐藏字段、派工空列表和计算价格失败做真实环境验收。对比请求日志中的 elapsedMs、promptTokens、cacheHitTokens 和工具 trace，分别统计冷缓存与重复提问的耗时、答案正确率，不以首条状态出现速度代替实际答复速度。

## 已知边界与后续工作

- 本轮自动测试使用本地证据与模拟模型/CRM 响应，不代表已验证真实组织中全部动态脚本、权限和插件代码，也未量化真实模型端到端提速比例。
- 原生组件识别目前仍使用名称前缀和自定义标志，不是完整的发布者归属审计；非标准命名需后续引入发布者/解决方案归属配置。托管不代表原生，保留原有有界查询限制。
- 最终证据排序是相关性启发式，不保证能恢复缺失的调用关系。跨程序集/反射分发仍依赖实际采集到的源码与工具能力。
- 本轮没有新增持久化后台聊天任务、断线重连恢复或 PluginTraceLog 查询工具；现有浏览器数据查询续传与任务持久化是不同能力。
- 反编译已有快照内缓存。本轮没有新增跨快照 DLL 缓存或全局业务数据缓存；实时数据仍经用户授权和当前 CRM 会话读取。

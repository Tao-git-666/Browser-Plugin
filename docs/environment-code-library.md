# 环境插件代码库：从目标实体反查写入来源

设备档案没有生成，不代表设备档案上的 Create 插件有问题。创建它的代码可能位于工单 Update、自定义 Action 或其他入口。环境代码库让 AI 跨当前实体查找这些来源。

## 如何使用

1. 更新并启动分析服务器，在 Edge 扩展管理页重新加载此插件，然后刷新 CRM 页面。
2. 打开插件右上角齿轮，确认已保存“允许分析插件代码”设置。
3. 点击“同步当前环境插件代码库”。这表示同意把当前登录用户可读取的自定义插件 DLL、注册目录及反编译源码保存在独立分析服务器。不会发送 CRM Cookie 或登录令牌。
4. 等待同步完成。首次会逐个下载、反编译 DLL，请保持侧栏打开且停留在同一 CRM 环境。同步失败的程序集会提示，成功部分仍可搜索。
5. 在正常窗体分析完成后提问，例如：“设备档案 new_equipment 由哪些插件创建或更新？我更新工单后没有生成，请检查来源和触发条件。”其中实体逻辑名应替换为你环境中真实的名称；不知道时可以只给业务名称。

部署 DLL 或调整注册步骤后重新同步。关闭侧栏会中断后续批次；再次同步会重新读取目录和 DLL，但相同内容的 DLL 可以复用服务器反编译缓存。

## AI 的检查路径

确认目标实体 → 搜索代码库 → 区分查询与实际 Create/Update → 追踪方法及调用入口 → 核对候选注册步骤 → 检查业务条件和提前退出 → 在有授权及运行证据时核对这次执行。

- `search_environment_code`：按实体逻辑名、方法名或业务词寻找候选 DLL，返回覆盖情况、代码片段和同步时间。
- `read_environment_code`：分段读取方法、其他命中位置和注册步骤。候选步骤不等于已确认的调用者，AI 仍须核对调用关系。
- `reverse-entity-writer` 排查 Skill：提醒模型检查源实体、注册消息、启用状态、阶段、同步/异步、过滤字段，以及代码中的 Target、状态、Depth、映像、查询为空、提前返回、异常处理。
- 已授权 CRM 数据读取时，可利用原有只读工具查询有关插件跟踪日志或异步任务；不会自动开启日志、重放请求或修改业务数据。

过滤字段关注更新请求是否包含指定列，不意味着该列值一定改变。[微软说明](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/best-practices/business-logic/include-filtering-attributes-plugin-registration)

## 缓存与更新

- 索引位于 `Storage:DataDirectory/code-library-v1`；DLL 和源码保存在已有工件存储中。
- 缓存键为 CRM 组织地址和 DLL 内容 SHA-256。同环境、相同内容复用源码；内容变化重新反编译。
- 每次同步生成新的注册快照，即使 DLL 未变化，也会刷新步骤过滤字段、状态等信息。新同步成功部分成为后续问答使用的代码库，缺失部分不会伪装成完整。
- 按组织地址和库标识隔离查询，切换组织或分析服务器不会自动使用另一个环境的库。此隔离不替代服务器身份认证与访问控制；多用户部署仍须按部署文档配置认证、访问范围和文件权限。
- 目前没有自动保留期清理和后台定时同步。旧库及工件会保留，应监控磁盘容量、按组织要求备份和管理源码访问权限。

## 能力边界

- 默认窗体采集仍只处理当前实体有关插件。只有用户主动同步代码库才会跨实体收集自定义程序集；不全表扫描微软原生步骤。托管的客户业务插件不会仅因“托管”而排除，已知微软原生名称会过滤。
- 每次最多发现 300 个程序集，逐 DLL 查询关联类型和步骤，分页和大小超限、权限不足、失败批次会降低覆盖度。环境更大时当前版本不保证完整索引。
- 仅能读取 CRM API 可返回的数据库 DLL。磁盘部署、不可下载的包、外部服务实现和未同步代码不可见。
- 注册信息是同步时快照。代码索引是文本/标识符检索，不是完整跨程序集调用图；反射、动态实体名、外部依赖仍可能造成断点。
- 不能仅凭源码断定“这一次执行了”。需要对应时间、记录或关联标识的运行证据。日志未开启、被清理或无权限时，查不到不等于没有触发。[本地版日志设置](https://learn.microsoft.com/en-us/dynamics365/customerengagement/on-premises/admin/system-settings-dialog-box-customization-tab?view=op-9-1)
- 给模型的片段会隐藏疑似凭据代码行，但简单规则不能保证识别所有硬编码秘密；完整源码和 DLL 在服务器保留，应仅同步你有权分析和交给所选模型处理的代码。

自动化回归覆盖 v8.2/v9.0/v9.2 请求路径、跨实体关系、托管客户插件、禁用步骤、缓存更新、组织隔离和许可关闭。真实本地版/在线版 CRM 的权限、定制及版本差异仍需在目标环境验证。

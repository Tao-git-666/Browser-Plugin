# 架构说明

## 信任边界

```text
D365 页面主世界
  └─ 公开 Xrm API + 同源只读 Web API
       └─ Edge 扩展隔离世界
            └─ HTTPS SnapshotUpload
                 └─ Windows 分析服务
                      ├─ 持久化快照/任务
                      ├─ 无执行静态分析
                      ├─ 低权限外部反编译 Worker
                      └─ 证据检索与回答
```

CRM 身份只存在于浏览器到 CRM 的请求中。独立服务器使用自己的 Windows 身份验证来识别访问者，但不模拟用户访问 CRM，从而避免把用户票据转发到后端和 Kerberos 双跳配置。

## 证据模型

分析器将原始文件转换为节点和边：

- 节点：窗体事件、字段、JavaScript 函数、Ribbon Command、CRM 消息、插件步骤、插件类型、程序集、反编译类型、Execute 入口和插件行为。
- 边：引用、调用、读取、修改、触发、由某程序集实现。
- 置信度：`Confirmed` 表示配置或 AST 的直接证据；`Inferred` 表示根据消息和实体进行的关联；`Unknown` 表示缺失依赖、动态代码或无法取得的文件。

当前实现由确定性的证据问答引擎生成中文回答和引用，不把源代码发送到外部模型。未来接入本地或企业模型时，也只能基于证据图润色；模型不可修改证据和置信度。

## 快照生命周期

1. 扩展取得当前页面上下文。
2. 只读取该窗体引用的组件，并记录每个组件的 ID、版本和来源 URL。
3. 内容以 Base64 传输，服务端校验类型、大小、哈希和 XML/PE 结构。
4. 快照与分析任务写入数据目录，后台 Worker 处理。
5. 浏览器只预取当前实体步骤引用的数据库 DLL；AI 选中具体步骤并调用源码工具时，外部进程才在随机临时目录按需反编译。派生 C# 以内容哈希缓存到该快照，进程结束后清理临时目录。
6. 问答只检索指定快照，不允许由问题触发任意 URL 下载。

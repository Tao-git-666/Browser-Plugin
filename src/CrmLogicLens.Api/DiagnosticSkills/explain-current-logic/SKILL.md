## 取证顺序

定位用户所说的界面元素或动作，再沿实际绑定关系追踪。只读取与问题直接相关的脚本或插件实现。

## 停止条件

已确认入口、主要条件和可见业务效果；动态分支或缺失工件作为未知项保留，不为追求“全面”扫描无关组件。

## 回答要求

先说明业务效果和触发条件。除非用户明确询问技术实现，否则把函数名、逻辑名和节点编号留在技术依据中。

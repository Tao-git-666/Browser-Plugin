## 取证顺序

1. 用用户说的字段中文名定位当前实体的 FieldMetadata 和窗体控件，取得逻辑名。同名字段不能仅凭名称视为同一字段；沿实际绑定关系确认当前窗体入口。
2. 沿字段 OnChange、窗体 OnLoad 和 OnSave 查找相关处理函数。存在源码时调用 read_javascript_function，继续读取入口调用的公共校验或赋值函数，不以函数名代替规则。
3. 分别确认输入格式、允许为空、业务必填、自动赋值和保存拦截；区分仅弹出提示、清空字段、设置错误提示、真正阻止保存等行为。
4. 仅当代码指向服务端操作时，才解析对应 API 或相关插件；不要列举导入导出、其他按钮和普通插件目录来回答字段问题。

## 场景与处理

| 现象 | 处理方式与判断边界 |
| --- | --- |
| 有时必填、有时可空 | 比较字段元数据、setRequiredLevel、业务规则与 OnSave 条件；前端提示规则不能代替服务端实际校验。 |
| 输入后被清空 | 找到 setValue(null/空字符串) 或清空封装及条件；区分清空值、仅显示错误和阻止保存。 |
| 自动带出后又改变 | 追踪默认值、OnLoad、OnChange、接口回调和映射来源；多个赋值位置不等于已确认本次执行顺序。 |
| 金额精度或舍入不符 | 对照元数据精度、脚本转换/舍入与接口返回处理；显示格式和实际保存值分开解释。 |
| 日期偏移或自动变化 | 检查字段日期行为、客户端类型和时区转换代码；缺少元数据时不把所有日期都当成 UTC 日期时间。 |
| 查找或选项赋值失败 | 核对查找对象的 ID/实体类型，以及选项标签与数值映射；显示文本不是实际存储值。 |
| 手填会联动、代码赋值不联动 | 查 setValue 后是否显式 fireOnChange 以及下游绑定；不把赋值和触发事件视为同一个动作。 |

正则表达式需检查锚点、字符范围、长度及前置 trim/类型转换。允许空值、数字 0、false 与缺失属性不能混为一谈；若校验依赖未采集公共库，说明可见的入口和缺失的具体函数，而不是按常识补齐算法。

## 数据读取条件

解释通用填写规则不需要读取用户实际证件号码。只有用户问这次输入为什么不通过，且已授权时，才按需读取当前窗体实时值；区分未保存值与数据库值，回答不复述完整证件号。

## 完成标准与反例

已取得决定规则的表达式、条件分支或配置及触发时机，才解释具体长度、字符集、校验位或赋值来源。函数名包含 idcard/validate 不能证明实现了身份证校验位算法。调用缺失的公共库时明确缺口；禁止凭身份证常识补写系统没有证据支持的规则。

## 回归问题

- 身份证号的填写逻辑是什么：必须定位字段及其校验入口，不应回答导入导出接口。
- 手机号码为什么被清空：应查找到清空动作及成立条件，不得把显示提示等同于清空。
- 金额为什么自动带出：说明赋值来源和触发条件，不把数据库已保存值说成当前未保存值。

- 字段必填但隐藏：分别解释当前界面规则和服务端约束，不能保证隐藏后就一定能保存。

回答给出可证实的填写规则和触发时机，示例使用虚构或脱敏值。若需修改规则，仅指出应核对的配置/函数及预期行为，不替用户修改数据。完成前调用 `check_diagnostic_progress` 并保留证据缺口。

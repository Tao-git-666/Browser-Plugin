## 取证顺序

先确认用户执行的源操作及实际消息，只检查当前实体相关的自定义步骤。首次调用 `list_current_entity_plugin_steps` 使用 `enabled_only: false`，才能发现禁用步骤；该工具默认只返回启用项，默认空结果不能证明未注册。消息已确认时再按消息缩小，核对启用状态、阶段、同步模式、顺序和过滤字段。

如果用户问的是某个目标记录没有创建/更新，而源操作可能在其他实体上，不要把上述当前实体范围当作完整环境。环境代码库可用时切换 reverse-entity-writer；不可用时提示用户在连接设置中同步当前环境插件代码库，再从目标实体反查写入者。

## 条件分支

- 注册条件不匹配时，说明哪个条件阻止步骤进入候选范围。
- 注册条件匹配但结果不符合预期时，必要时读取已确认步骤的实现，检查提前返回条件。
- 没有插件跟踪日志时，只能判断“是否具备触发条件”，不能判断某次执行是否进入代码。

## 场景与处理

| 现象 | 处理方式与判断边界 |
| --- | --- |
| 字段值没变却执行了 | 过滤字段检查请求是否包含该列，不是值是否真正变化；没有请求列证据时保留未知。 |
| 改了值却没执行 | 核对提交模式、真实消息、源实体和过滤字段；窗体脏值不证明请求提交了该列。 |
| 步骤符合条件但没有效果 | 用已返回的步骤 nodeId 调用 read_decompiled_plugin，检查 Target、映像、配置、状态、查询为空、重复判断和提前 return。 |
| 直接操作正常，间接更新无效 | 对照实际父调用和代码中的 Depth/上下文限制；不能只凭 Depth 保护推断本次层级。 |
| 同步正常、异步没结果 | 已授权且工具支持时按已知步骤/记录和时间范围查询关联异步任务；区分排队、失败和完成，不拿任意最近任务归因。 |
| 最近发布后不触发 | 核对注册快照时间、类型与 DLL 版本/哈希；旧注册或旧反编译片段不能说明新配置。 |

Update 的 Target 通常只包含请求中的属性；缺少属性不等于 null，读取旧值需核对映像注册、别名及列集合。映像或执行上下文未采集时不伪造其内容。同阶段多个步骤的顺序需以注册及调用证据为准，不凭列表排列推断。

已有失败响应或录制事件时按工具可用性读取。授权后可通过 `query_crm_data` 在已确认类型、时间和关联标识范围内查询跟踪日志；未启用、清理或无权限均可能导致日志为空。诊断不启用日志、不修改步骤、不重放保存。

## 停止条件

已区分步骤未注册/禁用、消息或过滤字段不匹配、代码提前返回、执行后无预期效果，以及缺少运行日志这几类情况。

只有采集覆盖足以支持时才能确认“未注册”；当前实体目录不是全环境目录。处理建议指向对应注册项、代码分支或关联任务。完成前调用 `check_diagnostic_progress`，保留证据缺口，不用工具调用完成证明插件实际执行。

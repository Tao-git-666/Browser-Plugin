## 取证顺序

确认是新建/更新、手动保存/自动保存/保存并关闭，以及是否发出了相关请求。先检查窗体 OnSave 及相关前端校验，已有失败响应时立即对照错误；证据指向服务端保存时，调用 `list_current_entity_plugin_steps` 按当前实体核对真实消息、阶段、同步模式和过滤字段。不为纯前端拦截强制扫描插件。

## 条件分支

- OnSave 调用 `preventDefault` 或校验函数时，读取对应脚本条件。
- 存在实际失败响应时，优先用错误文本定位同步服务端逻辑。
- 只有找到相关步骤且注册信息不足时，才读取插件实现。
- 保存成功后才发生异常时，检查异步任务或前端成功回调，不把它描述成保存前校验。同步 PostOperation 仍可能在保存事务中，不能仅凭阶段名称认定已经提交。

## 场景与处理

| 现象 | 处理方式与判断边界 |
| --- | --- |
| 没有请求，停在窗体校验 | 查必填、字段通知、OnSave 的 preventDefault 及其真实条件；缺少网络录制不等于已证实没请求。 |
| 手动正常、自动保存失败 | 读取 getSaveMode 相关分支和事件注册；按实际客户端版本核对行为，不把所有保存入口当成相同流程。 |
| 保存一直转圈或重复保存 | 检查 Promise、进度关闭与 OnSave 再次调用 save 的路径；不自动触发保存或循环重试。 |
| 响应提示重复、权限或并发冲突 | 对照实际错误文本和相关配置/代码，不仅按状态码猜唯一原因；处理建议指向具体约束，不直接删除记录或提高权限。 |
| 同步插件抛错后值恢复 | 关联步骤、异常和事务位置，区分同步回滚与页面显示；没有关联日志时不选任意插件作为抛错者。 |
| 主记录已保存，后续动作失败 | 区分已完成保存、异步写入与客户端回调异常；若只是值未变化，转到 data-not-updated。 |

平台服务端必填和窗体业务必填分别验证；字段隐藏/禁用不能证明服务端允许空值。OnSave 异步支持等在线特性需先核对本地部署版本与配置，不把文档中的新能力当作当前系统已启用。

## 停止条件

已区分前端取消、同步插件抛错、平台校验、事务回滚或保存后的异步处理；证据不足时说明缺少实际错误响应或插件跟踪日志。

回答给出保存停在哪一层、相关条件与证据，再给出对应的规则核对或补采建议。诊断不修改必填设置、禁用插件或重放提交。完成前调用 `check_diagnostic_progress`，保留 evidenceGaps。

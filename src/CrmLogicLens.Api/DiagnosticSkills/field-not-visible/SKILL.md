## 取证顺序

区分“当前 FormXML 没有控件”和“控件存在但运行时不可见”。依次核对控件、节和选项卡的静态可见性，再追踪调用 `setVisible` 的窗体事件。

## 条件分支

- 存在相关函数时才读取函数片段。
- 用户授权时，读取目标字段的实时值和控件 `visible` 状态。
- 未找到控件时，检查采集的窗体标识是否与用户当前看到的窗体一致。

## 停止条件

已确认控件缺失、容器隐藏、脚本条件或运行时状态之一；证据不足时说明仍需实际窗体、业务规则或权限证据。不能把“没有搜索到”写成“字段一定不在窗体上”。

## 精确回答与反例

- 用户问“服务类型为维修时隐藏哪些字段”，要找到服务类型的选项标签与值的对应关系，读取该条件分支中 setVisible 的目标控件，再转换为业务字段名称。只有 Update 插件注册信息不能回答这个问题。
- 同一字段可以有多个控件，头部控件与正文控件的状态可能不同；检查具体控件及父级节、选项卡，不以单个 visible 值代表所有显示位置。
- 运行时已隐藏只能证明当前状态；要说明原因还需要可见性设置来源。未取得业务规则、字段权限或相关脚本时，将其记为缺口而非已排除。
- 询问静态条件下的规则时不必读取实际记录；问题依赖当前值时才按授权读取条件字段，避免无关数据查询。

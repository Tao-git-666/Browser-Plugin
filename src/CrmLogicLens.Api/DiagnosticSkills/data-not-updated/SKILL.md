## 取证顺序

沿前端动作确认写入目标、字段和调用方式，再检查当前实体相关插件的阶段、同步模式、过滤字段和可能的二次更新。

## 条件分支

- 没有写入调用证据时，结论限定为“未确认发起写入”。
- 存在失败响应时，区分写入被拒绝与事务回滚。
- 写入成功后值不同，检查后续同步/异步逻辑覆盖和界面刷新。
- 只有答案依赖实际值时，才按授权查询当前记录的必要字段。

## 停止条件

把问题归入未发起写入、写入失败、事务回滚、后续覆盖、异步未完成、界面未刷新或证据不足之一。不能仅根据最终页面值断言服务端没有执行。

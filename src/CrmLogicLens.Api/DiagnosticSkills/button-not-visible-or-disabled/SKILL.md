## 取证顺序

先确认当前应用、实体、窗体或网格位置，定位按钮 ID 和绑定命令，区分“不显示”和“显示但禁用”，再分别检查 DisplayRule、EnableRule 和它们引用的函数。由 `find_business_logic` 返回的节点调用 `trace_evidence`，不凭显示标签猜命令 ID。

## 条件分支

- 规则调用 JavaScript 时，只读取对应规则函数。
- 规则依赖字段值、选择数量或窗体状态时，在用户授权后读取判断所需的最小数据。
- 找不到按钮定义时，保留“当前采集范围未找到”的边界，不得断言按钮不存在。

## 场景与处理

| 现象 | 处理方式与判断边界 |
| --- | --- |
| 选中记录后才出现或可用 | 检查 SelectionCountRule、实体类型和选中记录参数；当前窗体字段工具不能取得网格选择数量，缺失时说明需要的实际选择状态。 |
| 新建时没有，保存后出现 | 核对 FormStateRule、记录 ID 和脚本条件，区分新建/更新窗体；不自动保存来触发规则。 |
| 某人可见、某人不可见 | 检查已采集的权限规则、角色条件和调用用户；查不到完整权限计算时不能直接要求授予管理员角色。 |
| 改字段后仍灰色 | 检查规则依赖和 refreshRibbon 调用位置；代码存在刷新调用不证明本次已运行，不为排查执行页面脚本。 |
| 同名按钮在子网格正常 | 比较命令位置、定义和上下文参数，不混用主网格、子网格、窗体规则。 |
| 发布后仍旧样式 | 核对快照时间、当前应用和实际加载的资源；建议重新采集验证，不擅自发布解决方案或清理用户状态。 |

组合规则需按实际 XML 的 AND/OR、InvertResult 和默认值解释；CustomRule 要读取返回分支。异步规则的支持和超时行为需核对当前客户端版本，不能把在线版行为直接套到本地部署。微软内置或未采集规则保留为不可见实现。

## 停止条件

已确认控制按钮状态的规则及其当前条件，或已明确缺少应用级 Ribbon、运行时状态或权限证据。不要只根据按钮标签推断规则。

回答指出具体规则、条件来源和最小验证方式；只发现当前状态时不宣称已找到原因。完成前调用 `check_diagnostic_progress` 并保留证据缺口。

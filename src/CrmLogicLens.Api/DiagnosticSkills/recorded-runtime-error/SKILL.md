## 取证顺序

先读取未按错误类型过滤的录制事件，保留用户动作、页面/框架来源与时间，再定位目标操作后的首条相关异常。点击文本只能定位入口，不能证明后台逻辑；时间线上最早的错误也可能属于无关后台请求，需用路径、脚本文件或调用链确认关联。

工具返回有数量上限，录制也可能晚于入口操作；核对可见时间范围与缺口，不把最后可见事件当成必然的故障起点。已经存在的录制可直接用于本次诊断，缺少的现场证据不能通过自动重放补齐。

## 条件分支

- 时间线包含失败的 Dataverse API/Action 时，从实际路径和响应确定 operation，再追踪相关脚本与实现。
- 只有 JavaScript 或 Promise 异常时，围绕函数名、文件名和错误文本读取脚本。
- 只有证据链明确落到 Create/Update/Delete 消息时，才读取当前实体插件步骤。

## 场景与处理

| 录制情况 | 处理方式与判断边界 |
| --- | --- |
| 多个并行请求一起报错 | 依据请求路径、时间、可用关联标识及调用函数分组；时间相邻不能证明因果关系。 |
| JS 错误后出现通用弹窗 | 先追踪与目标操作相关的异常及 catch/提示包装，区分原始异常和二次提示，避免当成多个独立根因。 |
| 只有脚本文件或压缩堆栈 | 用文件、已知函数和错误词定位；缺少源文件/映射时停在可证明的代码边界，不编造行号。 |
| 没有红色报错但列表为空 | 查询工具可用时读录制的 Dataverse 查询，按空列表场景重新匹配；0 条结果不属于 HTTP 故障。 |
| 只录到错误弹窗 | 说明入口和前置请求可能未覆盖，保留现有错误证据，建议用户从操作前开始完整录制。 |
| 多个同源 iframe 或重复提示 | 核对 frame/来源和事件信息（仅当结果实际提供）；相同错误文本可能重复记录，也可能是不同调用，不机械合并。 |
| 没有任何相关错误 | 说明本次录制未观测到，不推断操作成功；已知未捕获的外部接口或控制台范围属于采集边界。 |

录制不包含请求体、键盘输入或响应记录。不能据时间线还原敏感字段值；确有必要时只能在既有授权范围内读取最小字段集合。

## 停止条件

已将相关操作、首条相关错误和静态代码对应起来，或已明确缺少响应正文、脚本工件或调用关系。已确认直接原因时先说明原因；否则先说明已定位的失败环节，不把未知原因写成事实。给出最短的补采/验证步骤，完成前调用 `check_diagnostic_progress` 并保留 evidenceGaps。

## 取证顺序

定位打开自定义页面或 HTML Web Resource 的按钮，再沿 `opens-custom-page` 和 `loads-script` 关系确认页面及其脚本。

## 条件分支

- 存在录制查询时，优先检查返回 0 条的查询，提取实体、字段、运算符、联表和排序。
- 已定位页面脚本时，读取构造 `$filter`、FetchXML、查询参数或候选集合的相关函数，并说明条件来源。
- 筛选值已脱敏且结论依赖实际值时，只在授权后读取最小范围的窗体值或 CRM 数据。
- 没有录制查询时，基于静态证据回答并建议重新录制完整的页面打开过程；不要反复请求不存在的运行时工具。

## 停止条件

已确认实际查询或静态筛选结构及其来源，或者已明确查询未被录制、脚本缺失、使用非 Dataverse 接口或本地缓存。请求成功但返回 0 条不是接口报错。

## 条件来源与权限边界

把实际过滤条件逐项关联到页面参数、当前工单字段、登录用户、配置或代码常量。跟进构造查询的公共函数和页面初始化函数；只看到打开页面的函数不算定位了人员筛选逻辑。

授权且工具支持时，可用最小范围的只读查询验证候选记录或计数。不要自动删除过滤条件来扫描全部人员；不支持计数或数据已脱敏时，说明尚不能验证哪项条件排除了记录。多个条件可能共同产生空结果，不能仅根据单项条件就认定唯一原因。

当前用户查不到不等于组织中不存在该记录，仍可能受所有权、共享、业务部门或字段权限影响。不得重放派工、提交等写请求，不得修改查询结果或业务状态。

## 回归问题

“派工弹窗没有可用人员，筛选条件是什么”：答案需包含有证据的筛选规则及来源，区分静态规则、实际查询与尚未验证的候选数据，不能只回答“请检查权限”。

## 取证顺序

先确认列表位于自定义页面、HTML Web Resource、查找控件还是标准子网格。对于自定义页面，定位打开页面的按钮，沿 `opens-custom-page` 和 `loads-script` 关系确认页面及其脚本；标准控件则追踪当前控件、视图和过滤脚本，不假定存在打开页面的按钮。

## 条件分支

- 存在录制查询时，优先检查返回 0 条的查询，提取实体、字段、运算符、联表和排序。
- 已定位页面脚本时，读取构造 `$filter`、FetchXML、查询参数或候选集合的相关函数，并说明条件来源。
- 筛选值已脱敏且结论依赖实际值时，只在授权后读取最小范围的窗体值或 CRM 数据。
- 没有录制查询时，基于静态证据回答并建议重新录制完整的页面打开过程；不要反复请求不存在的运行时工具。

## 场景与处理

| 现象 | 处理方式与判断边界 |
| --- | --- |
| 请求返回 0 条 | 检查同次操作的实际查询，逐项解释 AND/OR、空值、关联过滤和日期条件；脱敏值不能当作真实筛选值。 |
| 请求有结果但页面空白 | 检查响应结构读取、客户端二次过滤、分页、绑定和渲染异常；返回条数不代表每条都通过前端筛选。 |
| 切换条件后偶尔为空 | 追踪条件赋值、查询发起顺序与回调覆盖；时间上接近的两个请求不一定使用同一条件。 |
| 只有部分用户查不到 | 核对过滤中当前用户/团队来源；只读查询沿用当前用户权限，不能据此推断管理员或其他用户的结果。 |
| 查找器或子网格无记录 | 定位默认视图、关系约束、addPreSearch/addCustomFilter 等实际引用；未采集视图或关系定义时明确缺口。 |
| 只有前一页或缓存数据 | 查分页游标、后续请求和缓存使用代码；不支持的外部查询或返回体不能通过猜测补齐。 |

先按 `empty_only: true` 找空查询；不能解释页面现象时，再用实体或字段关键词查同次录制的非空查询，避免漏掉“后端有数据、前端丢弃”。工具有返回数量上限，没有匹配结果不能证明这次没有查询。日期/状态筛选需核对实际字段类型、选项值和转换代码，不按标签或本机时间猜值。

## 停止条件

已确认实际查询或静态筛选结构及其来源，或者已明确查询未被录制、脚本缺失、使用非 Dataverse 接口或本地缓存。请求成功但返回 0 条不是接口报错。

## 条件来源与权限边界

把实际过滤条件逐项关联到页面参数、当前工单字段、登录用户、配置或代码常量。跟进构造查询的公共函数和页面初始化函数；只看到打开页面的函数不算定位了人员筛选逻辑。

授权且工具支持时，可用最小范围的只读查询验证候选记录或计数。不要自动删除过滤条件来扫描全部人员；不支持计数或数据已脱敏时，说明尚不能验证哪项条件排除了记录。多个条件可能共同产生空结果，不能仅根据单项条件就认定唯一原因。

当前用户查不到不等于组织中不存在该记录，仍可能受所有权、共享、业务部门或字段权限影响。不得重放派工、提交等写请求，不得修改查询结果或业务状态。

## 回归问题

“派工弹窗没有可用人员，筛选条件是什么”：答案需包含有证据的筛选规则及来源，区分静态规则、实际查询与尚未验证的候选数据，不能只回答“请检查权限”。

“列表请求返回 5 条但仍不显示”：应追踪客户端处理，而不是继续推断服务器筛选无结果。完成前调用 `check_diagnostic_progress`，保留未采集视图、查询或代码的缺口，给出相应的补采或验证步骤。
